Audit trail

Definitions and source coverage

Missing or stale required sources are marked partial or delayed instead of being presented as zero.

What counts as a participating account?

One namespaced GitHub login, Base wallet, or normalized self-reported comment author with a qualifying action in the period. Namespaces are not merged, so this is participation—not verified unique people.

What counts as payout volume?

Solver reward, verifier reward, and timeout completion bonus from every confirmed, block-time-verified BountySettled event across both live protocols, plus verifier pay from confirmed rejected-submission events. Recovery reservations affect future earning safety, never immutable payout history.

What counts as GMV?

Only confirmed canonical settlement events. Funding plans, approvals, deposits, transaction broadcasts, advisory verdicts, and rejected-submission verifier payments do not count as GMV.

How is the claim completion rate calculated?

An exclusive-claim (network, bounty_id, round) whose deadline has passed or that already has a terminal canonical event. Immature claims are shown separately. Open Competition has no exclusive claim and stays outside this cohort.

How are repository users counted?

GitHub reports unique cloners and unique visitors for a rolling 14-day window. Both unique counts are shown as repository users, but GitHub does not expose their identities or overlap. They therefore remain separate and are not added to external active identities.

What is deliberately excluded?

Bots, maintainers in the public policy, browser visitors, stars, repository traffic from active platform identity totals, returned claim bonds, refunds, funding intentions, unconfirmed transactions, leaderboard prizes, and private operational analytics.

Only a confirmed canonical BountySettled or CompetitionSettledV2 event proves solver payment, depending on the protocol version.
