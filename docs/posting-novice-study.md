# Posting comprehension pilot — not yet run

Status: **WAIVED by the user/maintainer on 2026-09-17; zero participants. This is retained only as an optional research plan, not a release gate.** Agent inspection and content tests
cannot substitute for this pilot. Recruit five people unfamiliar with the
platform through a separately authorized process. No invitations were sent.

Give every participant the same isolated staging environment, device allocation
(three desktop, two phone), supported fixed task, test funds and neutral prompt:

> Prepare a bounty for a Markdown file containing three concrete examples of
> company digital work. Each example should describe the missing information
> or computing resource, requested output and a measurable completion check.
> Use a total reward budget of 2.01 USDC and the displayed exact calendar
> deadline. Review the available ways to check the work, then finish posting
> using the test wallet when you are comfortable.

Use one fixed ISO deadline with offset, recorded before the first session and
identical for all five. Keep the displayed network fee scenario identical.
Explain only that this environment uses test money. Do not explain interface
steps, define the reviewer or point at the correct button. Technical setup may
be completed beforehand; record it separately from procedural assistance.

Before the first payment authorization, ask these neutral questions verbatim:

1. What are you buying?
2. How will it be decided whether the work is complete?
3. What will this cost you?
4. What will happen when you choose the next action?

Record answers verbatim in `posting-novice-results.csv`, along with exact
mistakes, pauses, assistance and completion evidence. Avoid identifiers,
credentials, account-recovery data and wallet secrets. Never screenshot QR codes.

Score against the approved task, chosen review mode, exact reward/reserve,
additional network fee and actual payment-authorizing action. Count completion
only when the same bounty has all four signals: creation, funding, claimability
and matching public inventory. The observer must not coach a stuck participant
until their unaided attempt has been recorded as unsuccessful; later assisted
completion is a separate result. Record elapsed time, but do not invent a time
limit or treat speed as an acceptance threshold.

Precommitted targets: **at least 4/5 unaided completions**, and **5/5 participants
correct on all four prepayment questions**. Report successes/attempts, raw
answers, mistakes and assistance. Do not exclude failures or silently replace
participants. If any criterion fails, identify the relevant change and repeat
with a new, clearly labeled cohort. This is a small usability pilot, not
statistical proof or a production payment test.
